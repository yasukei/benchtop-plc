# Internationalization

The web package uses a small typed catalog rather than a translation library. Two
bundled locales and plain argument templates need no additional dependency, and
TypeScript checks both message keys and core diagnostic argument contracts.

`catalog.ts` defines shell messages and `MessageKey`. `diagnostic-catalog.ts`
defines one template per `DiagnosticCode` in each locale. Templates receive the
matching `DiagnosticArgs` and `formatDiagnostic(language, diagnostic)` renders
compiler, project and runtime diagnostics. Identifiers, ST keywords and IEC types
retain their spelling. Stable suggestion and syntax identifiers are localized;
argument positions are shown as one-based numbers.

`createI18n` is a plain TypeScript external store. Initialization prefers a valid
saved selection, then the first supported entry in `navigator.languages` (including
regional English/Japanese tags), then English. The language selector updates all
shell labels, accessible names, banners and the active diagnostic without reload
or runtime commands. The selection is saved under `benchtop-plc.language` in
localStorage. Storage access/read/write failures leave switching usable in memory.
The browser adapter also updates `html.lang` and the document title.

## Adding messages

Add shell keys to both `en` and `ja`; render with a typed catalog lookup. Add new
core diagnostic codes to both diagnostic catalogs and the exhaustive argument
examples in `diagnostic-catalog.test.ts`. Unit tests check exact locale key parity,
full diagnostic coverage and rendering. Browser tests cover language detection,
switching, preference persistence, blocked storage and displayed fault translation.

The ESLint `no-restricted-syntax` configuration rejects non-whitespace JSX text,
direct string expressions, template literals, conditional string results and
user-facing attribute literals (including `aria-label`, `title`, `alt` and
`placeholder`). Structural attributes such as class names, IDs and option values
are allowed. A lint regression test verifies rejection of hard-coded JSX examples.
Data supplied by the compiler/runtime remains locale-independent.
